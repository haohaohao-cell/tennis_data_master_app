# 击球检测算法

本文说明生产流水线当前使用的击球检测实现。对应代码为
`cv.events.hit_detection.standalone_get_ball_shot_frames`，调用位置在
`cv.pipeline.inference.run_inference_v2`。

该算法不直接识别球拍，而是联合使用以下信号推断击球帧：

1. 网球轨迹在当前帧附近是否发生方向突变；
2. 网球是否足够接近某个球员的检测框；
3. 相邻候选是否属于同一次轨迹抖动或同一次挥拍。

## 输入与输出

输入：

- `ball_positions`：逐帧网球框，生产流水线将轨迹中心扩展为边长约 10 px 的框；
- `player_detections`：逐帧球员检测框，格式为 `{player_id: [x1, y1, x2, y2]}`；
- `frame_height`：视频画面高度，用于远近端透视补偿。

输出：

- `clean_final_hits`：最终击球帧；
- `candidate_frames`：通过方向突变和人球距离过滤的候选帧；
- `clean_hit_players`：与最终击球帧一一对应的球员 ID。

## 1. 球心坐标

算法先把每帧网球框转换为中心点：

```text
x_t = (x1_t + x2_t) / 2
y_t = (y1_t + y2_t) / 2
```

视频像素坐标以左上角为原点：`x` 向右增大，`y` 向下增大。因此，画面近端通常具有更大的 `y`，远端通常具有更小的 `y`。

## 2. 前后窗口与突变分数

单帧检测坐标会因热力图峰值、框选误差和视频模糊发生抖动。如果直接比较相邻两帧，某一次像素跳动就可能被误判为击球。当前算法分别使用当前帧之前 3 帧和之后 3 帧的均值作为两侧轨迹基线：

```text
prev_x(t) = mean(x[t-3], x[t-2], x[t-1])
next_x(t) = mean(x[t+1], x[t+2], x[t+3])

prev_y(t) = mean(y[t-3], y[t-2], y[t-1])
next_y(t) = mean(y[t+1], y[t+2], y[t+3])
```

当前帧不参与两侧均值，避免突变点本身稀释突变幅度。方向突变分数为：

```text
score_x(t) = (x_t - prev_x(t)) + (x_t - next_x(t))
           = 2*x_t - prev_x(t) - next_x(t)

score_y(t) = (y_t - prev_y(t)) + (y_t - next_y(t))
           = 2*y_t - prev_y(t) - next_y(t)
```

这个计算衡量当前点相对前后轨迹均值的偏离程度。稳定移动或小幅随机抖动会被窗口均值部分抵消；发生明显折返时，当前点会同时偏离前后两侧均值，分数绝对值随之增大。

用于候选排序的总轨迹能量为：

```text
E_t = |score_x(t)| + |score_y(t)|
```

## 3. 方向候选阈值

满足下面任意一个条件即视为方向突变候选：

| 条件 | 阈值 | 画面含义 |
| --- | ---: | --- |
| `score_y > 10` | 10 px | 当前点在前后均值下方，形成 V 型突变 |
| `score_y < -3` | -3 px | 当前点在前后均值上方，形成倒 V 型突变 |
| `score_x > 3` | 3 px | 当前点在前后均值右侧 |
| `score_x < -3` | -3 px | 当前点在前后均值左侧 |

这些阈值是非对称的。它们是当前实现的经验参数，不表示四个方向具有完全相同的物理概率。

## 4. 人球距离

方向突变也可能来自落地、噪点或轨迹修正，因此算法要求球靠近某个球员。对球心 `(x_t, y_t)` 与球员矩形 `[px1, py1, px2, py2]`，先计算球心到矩形的水平、垂直间隔：

```text
dx = max(px1 - x_t, 0, x_t - px2)
dy = max(py1 - y_t, 0, y_t - py2)
```

再计算欧氏距离：

```text
D = sqrt(dx^2 + dy^2)
```

当球心位于球员框内时，`dx = dy = 0`。算法遍历当前帧所有球员，选择 `D` 最小的球员作为击球候选人。

## 5. 远近端透视补偿

同样的真实距离在画面远端只占较少像素，在近端会占较多像素。如果全场使用固定的人球像素距离阈值，要么容易漏掉近端击球，要么容易把远端噪点关联到球员。

当前实现使用球员框底边 `py2` 估计球员所处的画面深度：

```text
r = clip(py2 / frame_height, 0, 1)
T(r) = 30 + r * (150 - 30)
```

其中：

- `r` 越接近 0，球员越靠画面上方，即远端；
- `r` 越接近 1，球员越靠画面下方，即近端；
- `T` 是允许的人球最大像素距离。

线性缩放示例：

| `py2 / frame_height` | 位置 | 距离阈值 `T` |
| ---: | --- | ---: |
| 0.00 | 最远端 | 30 px |
| 0.25 | 偏远端 | 60 px |
| 0.50 | 画面中部 | 90 px |
| 0.75 | 偏近端 | 120 px |
| 1.00 | 最近端 | 150 px |

只有 `D < T(r)` 时才保留候选。除此之外，当球员位于画面远半场（`py2 <= frame_height * 0.5`）时，代码会排除 `score_y > 10` 的 V 型候选，用于减少远端落地反弹被识别为击球的情况。

这里的透视补偿作用于“人球关联距离”，并没有修改轨迹突变分数本身。

## 6. 候选聚合与窗口去抖

一次真实击球可能在连续多帧产生突变分数。算法把相邻候选帧间隔小于 12 帧的候选归入同一组，并只保留组内综合得分最高的候选：

```text
rank_score = 5 * E_t + 0.5 * (200 - D)
```

其中 `E_t` 强调轨迹突变强度，`D` 较小时距离项更高。当前权重使轨迹能量成为主要排序依据，人球距离用于辅助选择最接近真实触球时刻的帧。

这一步承担时间维度上的非极大值抑制作用：连续抖动不会输出多个击球事件，而是压缩为一个代表帧。

## 7. 同一次挥拍去重

完成候选聚合后，算法继续比较相邻事件的球员 ID。如果两个相邻事件：

```text
same_player == true
next_frame - current_frame < 30
```

则认为它们可能来自同一次挥拍的前摇或重复识别，并丢弃较早事件、保留较晚事件。最终击球帧与击球球员 ID 保持一一对应。

30 是帧数，不是固定时长。对应时间应按视频帧率计算：

```text
duration_seconds = 30 / fps
```

例如 30 FPS 时为 1 秒，60 FPS 时为 0.5 秒。

## 8. 与落点检测的冲突抑制

生产流水线会先分别生成击球和落点候选。为了避免同一个轨迹突变同时被标记为击球和落点，落点帧如果位于任一最终击球帧的正负 6 帧内，会从最终落点列表中移除。

因此击球结果在这段冲突窗口中具有更高优先级。

## 参数汇总

| 参数 | 当前值 | 作用 |
| --- | ---: | --- |
| 前窗口 | 3 帧 | 计算进入当前点之前的轨迹均值 |
| 后窗口 | 3 帧 | 计算离开当前点之后的轨迹均值 |
| 远端距离阈值 | 30 px | 限制远端人球关联范围 |
| 近端距离阈值 | 150 px | 放宽近端人球关联范围 |
| 候选聚合间隔 | `< 12` 帧 | 合并连续轨迹突变 |
| 轨迹能量权重 | 5 | 选择组内最强突变 |
| 人球距离权重 | 0.5 | 辅助选择组内候选 |
| 同球员去重间隔 | `< 30` 帧 | 合并同一次挥拍的重复事件 |
| 击球/落点抑制窗口 | `+-6` 帧 | 避免同一突变重复分类 |

## 当前实现限制

- `last_hit_frame` 初始化为 `-100`，循环中虽然检查 15 帧间隔，但该变量没有更新，因此这项检查目前没有产生实际抑制效果。实际去抖来自 12 帧候选聚合和 30 帧同球员剪枝。
- 窗口计算要求前后 3 帧坐标均有效；缺失坐标会使对应帧无法成为候选。
- 透视补偿使用球员框底边在画面中的相对高度，是线性近似，不等价于完整的相机标定或单应变换。
- 阈值均以像素和帧为单位，对分辨率、帧率或机位变化不天然保持一致。
- 本文只描述生产实现，不包含 experiment notebook 中的透视分数缩放和分段 RANSAC。

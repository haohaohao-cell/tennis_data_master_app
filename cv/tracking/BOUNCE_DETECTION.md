# 落点检测算法

本文说明生产流水线当前使用的落点检测实现。候选检测与落点坐标细化位于
`cv.tracking.bounce.BounceDetectorManager`，界内外判定由
`cv.events.in_out.evaluate_bounces_in_out` 完成，调用位置在
`cv.pipeline.inference.run_inference_v2`。

生产流水线中的处理顺序为：

```text
球轨迹坐标
  -> 垂直突变与方向夹角打分
  -> 局部极大值抑制
  -> 入射/出射直线交点细化
  -> 移除击球附近的冲突落点
  -> 单应变换到真实球场
  -> 界内/界外判断
```

## 输入与输出

`BounceDetectorManager.detect` 接收逐帧球心坐标：

```text
coords[t] = (x_t, y_t) 或 None
```

返回：

- `bounces`：经过阈值和局部极大值抑制后的落点候选；
- `scores`：每一帧的综合落点评分；
- `angles`：每一帧入射与出射运动向量的夹角。

候选中包含 `frame`、`coord`、`score` 和 `angle`。后续坐标细化会增加 `sub_coord`、`line_in` 和 `line_out`；界内外判断会增加 `is_in_bounds` 和 `bounce_type`。

## 1. 前后 5 帧窗口

默认 `half_window = 5`。对候选帧 `t`，算法读取：

```text
[t-5, ..., t-1, t, t+1, ..., t+5]
```

即总共 11 帧。窗口内任意坐标为 `None` 或横坐标为 `NaN` 时，当前帧直接跳过。

画面坐标的 `y` 轴向下。球触地时通常到达局部最低画面位置，即 `y_t` 相对触地前后更大。基础垂直突变分数为：

```text
prev_y(t) = mean(y[t-5], ..., y[t-1])
next_y(t) = mean(y[t+1], ..., y[t+5])

base_score(t) = 2*y_t - prev_y(t) - next_y(t)
```

与逐帧差分相比，前后均值能削弱单帧坐标抖动。真实落地反弹会让当前点同时低于入射和出射轨迹，因此产生较大的正分数；近似直线运动或随机小抖动的前后偏差更容易互相抵消。

## 2. 入射与出射方向夹角

仅依赖 `y` 方向局部极值仍可能把轨迹噪声识别成落点。算法另外使用前后 3 帧均值计算运动向量：

```text
v_in  = p_t - mean(p[t-3], p[t-2], p[t-1])
v_out = mean(p[t+1], p[t+2], p[t+3]) - p_t
```

夹角通过点积计算：

```text
theta = arccos(
    dot(v_in, v_out) / (norm(v_in) * norm(v_out))
)
```

`theta` 接近 0 度表示球基本沿原方向继续运动；角度增大表示轨迹在当前帧附近发生更明显的折转。零长度向量按 0 度处理。

角度对基础分数的修正规则为：

```text
angle_modifier = -30, theta < 5 degrees
angle_modifier = +10, theta > 20 degrees
angle_modifier =   0, otherwise

score(t) = base_score(t) + angle_modifier
```

含义如下：

- 小于 5 度：轨迹几乎没有改变方向，即使存在局部 `y` 波动也强烈降权；
- 大于 20 度：存在明显反弹形态，对候选加分；
- 5 到 20 度：保留基础垂直突变分数，不额外修正。

## 3. 阈值与局部极大值抑制

默认候选阈值为：

```text
score(t) > 15
```

通过阈值后，还要求当前分数等于正负 5 帧窗口内的最大值：

```text
score(t) == max(score[t-5 : t+5])
```

这一步是局部非极大值抑制（NMS）。一次落地可能连续多帧超过阈值，但最终只保留局部峰值帧，从而减少轨迹抖动造成的重复落点。

需要注意，代码使用严格的浮点值相等比较。如果局部窗口内存在完全相同的最大分数，可能保留多个并列峰值。

## 4. 落点坐标细化

离散视频只能把落点定位到某一帧。为了估计入射轨迹与出射轨迹的交会位置，`enhance_subpixel` 默认取落点前后各 4 帧，分别对 `x(t)` 和 `y(t)` 做一次直线拟合：

```text
x_in(t)  = vx_in  * t + bx_in
y_in(t)  = vy_in  * t + by_in

x_out(t) = vx_out * t + bx_out
y_out(t) = vy_out * t + by_out
```

先根据两条 `y(t)` 直线求交会时间：

```text
t_cross = (by_out - by_in) / (vy_in - vy_out)
```

再使用入射直线计算交点：

```text
sub_x = vx_in * t_cross + bx_in
sub_y = vy_in * t_cross + by_in
```

满足以下任一条件时放弃交点结果，退回原候选帧坐标：

- 入射侧或出射侧少于 2 个有效点；
- `|vy_in - vy_out| < 1e-6`，两条垂直运动直线近似平行；
- 交点不是有限数值；
- `|t_cross - bounce_frame| > 3`，交会时间离候选帧过远；
- 直线拟合或计算过程抛出异常。

函数名使用 `subpixel`，但当前实现最终将交点坐标转换为整数，因此保存的是“由连续时间直线交点修正后的整数像素坐标”，并非保留小数精度的亚像素坐标。

## 5. 与击球事件的冲突抑制

击球和落地都会造成轨迹方向突变。生产流水线在获得最终击球帧后，移除击球点附近的落点候选：

```text
abs(bounce_frame - hit_frame) <= 6
```

也就是击球帧正负 6 帧内的落点不会进入最终列表。这可以避免同一个突变同时被解释为击球和落地，但也意味着非常接近击球事件的真实落点可能被抑制。

## 6. 像素坐标到真实球场坐标

界内外判断优先使用细化坐标 `sub_coord`，不存在时使用原始 `coord`。算法取落点帧对应的球场单应矩阵 `H`，使用逆矩阵将视频像素映射到球场模板：

```text
[canvas_x, canvas_y, w]^T = inverse(H) * [pixel_x, pixel_y, 1]^T

canvas_x = canvas_x / w
canvas_y = canvas_y / w
```

再把模板像素换算为米：

```text
real_x = (canvas_x - 120) / 30
real_y = (canvas_y - 150) / 30
```

其中模板偏移为 `(120, 150)` px，比例尺为 `30 px/m`。

## 7. 界内与界外

当前 pipeline 按单打球场判断：

```text
球场宽度 = 8.23 m
球场长度 = 23.77 m
压线容差 = 0.05 m
```

判断条件为：

```text
-0.05 <= real_x <= 8.23 + 0.05
-0.05 <= real_y <= 23.77 + 0.05
```

满足条件时：

```text
is_in_bounds = true
bounce_type = "in"
```

否则为 `out`。双打模式会把宽度改为 `10.97 m`，但当前生产流水线明确传入 `match_type="singles"`。

如果坐标、帧索引或单应矩阵不可用，或者矩阵不可逆，当前实现保留默认值 `is_in = True`。这是防止流水线中断的容错策略，但会把无法判定的落点归为界内，而不是输出未知状态。

## 8. 透视处理边界

生产落点检测的候选阶段仍使用统一像素参数：

- 所有画面区域使用相同的 `score > 15`；
- 所有画面区域使用相同的前后窗口；
- 角度修正和 NMS 窗口不随球所在远近位置变化。

因此，落点候选分数本身没有像击球模块那样进行远近端线性缩放。远端球每帧像素位移较小，可能比近端更难超过统一阈值。

当前生产实现只在候选产生之后，通过球场单应变换消除透视对界内外坐标的影响。单应变换解决的是“落点在真实球场哪里”，不解决“远端轨迹突变分数是否足够大”。experiment notebook 中可能存在额外的透视分数策略，但不属于本文描述的生产算法。

## 参数汇总

| 参数 | 当前值 | 作用 |
| --- | ---: | --- |
| 落点半窗口 | 5 帧 | 计算前后垂直轨迹均值 |
| 向量窗口 | 3 帧 | 估计入射与出射方向 |
| 小角度惩罚 | `< 5 degrees: -30` | 排除近似直线运动 |
| 大角度奖励 | `> 20 degrees: +10` | 增强明显反弹候选 |
| 落点分数阈值 | `> 15` | 过滤弱突变 |
| NMS 半窗口 | 5 帧 | 合并连续候选峰值 |
| 坐标细化窗口 | 4 帧/侧 | 拟合入射与出射直线 |
| 最大交点时间偏差 | 3 帧 | 排除不合理交点 |
| 击球冲突窗口 | `+-6` 帧 | 防止击球被重复识别为落点 |
| 球场模板比例尺 | 30 px/m | 模板坐标换算为米 |
| 压线容差 | 0.05 m | 将压线附近落点视为界内 |

## 当前实现限制

- 11 帧检测窗口要求全部坐标有效，短暂丢球可能使真实落点无法参与打分。
- 候选阈值以像素为单位，没有按分辨率或远近端透视缩放。
- 坐标细化使用局部直线近似，而且最终交点会转换为整数像素。
- NMS 对并列最大值可能输出多个候选。
- 击球冲突抑制固定使用帧数，实际时间长度随视频 FPS 改变。
- 单应矩阵缺失或失效时默认判为界内，调用方无法区分“确认界内”和“无法判断”。
- 本文只描述生产实现，不包含 experiment notebook 中的分段 RANSAC 或透视分数调整。

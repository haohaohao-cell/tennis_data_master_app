# 轨迹实验开发日志

本日志只记录 `cv/experiments` 中的轨迹实验，不代表主项目 `cv/tracking` 已同步这些逻辑。

## 2026-08-01 - 冻结区间的 H0/H1 显式竞争

### 改进

- 对每个冻结可疑区间增加单模型 H0 与左右分支 H1 的确定性 RANSAC 比较。
- H0 对低内点覆盖率增加惩罚，避免单模型只解释一侧时得到虚假的低中位残差。
- 只有同时满足残差改善、速度方向或速度比突变、右侧分支持续和边界帧贴合右模型时，才确认事件边界。
- 诊断 JSON 增加 `h0_median_error_px`、`h1_median_error_px`、`h1_residual_improvement_px`、`h1_residual_improvement_ratio`、`event_persistence_points` 和 `h1_event_accepted`。

### 验证

- 保留原有尖刺、短缺口、边界 raw 保留和连续污染段回归测试。
- 新增断言：连续污染段必须通过 H1，孤立尖刺不得通过 H1。

## 2026-07-17 - 突变区间内的点级抖动过滤

### 背景

上一版在确认某个可疑区间包含真实轨迹突变后，会保留整个区间。这能避免击球点、落地点被平滑掉，但也会把区间内混入的抖动点一起保留。

### 改进

- 保留“区间左右分别拟合”的突变判断：
  - 左模型使用可疑区间之前的轨迹点；
  - 右模型使用可疑区间之后的轨迹点；
  - 左右模型在区间内的位置可以衔接，且速度夹角明显变化时，将该区间视为真实突变候选。
- 将保护粒度从“整个可疑区间”改为“区间内单点判断”：
  - 接近左模型的点作为突变前轨迹保留；
  - 接近右模型的点作为突变后轨迹保留；
  - 同时远离左右模型的点继续作为抖动或误检纠正。
- 增加区间支持约束：
  - 原始点到左右模型的支持阈值比例为 `0.65`；
  - 至少 `35%` 的有效区间点需要得到左模型或右模型支持；
  - 点的左右模型归属不允许出现从右模型重新跳回左模型的反向切换。
- 新增输出掩码：
  - `breakpoint_keep_mask`：真正需要保留的突变轨迹点；
  - `breakpoint_run_mask`：包含真实突变的完整候选区间；
  - `breakpoint_frames`：最终选出的突变代表帧。

### `long4` 当前核心结果

使用 `cv/data/output/long4_ball_coords_raw.json`，共 929 帧：

| 项目 | 数量 |
| --- | ---: |
| 初始可疑点 | 49 |
| 合并后的可疑区间点 | 56 |
| 检出的突变事件 | 4 |
| 被保护的突变轨迹点 | 20 |
| 被纠正的抖动或异常点 | 23 |
| 短缺口补点 | 51 |
| 证据不足而保留的点 | 6 |

当前检测到的突变代表帧为 `47`、`215`、`283` 和 `390`。该结果仍属于实验参数结果，不应直接视为击球或落地真值。

### 当前限制

- 第二遍 RANSAC 仍会在拟合输入中排除完整可疑区间，只是在输出阶段区分需要保留的突变点和需要纠正的抖动点。
- 已在 `trajectory_guarded_optimization.py` 中实现单模型 H0 与双模型 H1 的显式评分竞争；仍需用真实比赛片段标定改善阈值。
- 现有视频或 PNG 可能由较早参数生成。修改参数后需要重新运行 notebook 的 Window RANSAC、坐标图和视频输出单元。

### 下一步

- 使用 H1 相对 H0 的残差改善、右分支持续性、边界帧贴合和速度跳变共同决定是否确认边界。
- 后续仍需在真实视频上评估阈值，并将确认的边界提供给正式的击球/落地分段流程。

## 2026-07-16 - 真实轨迹突变保护与视频叠加

### 背景

两遍 Window RANSAC 能处理连续异常点，但会把击球、落地等真实速度突变误判为异常并替换为平滑预测值。

### 改进

- 对每个可疑区间分别拟合左侧和右侧轨迹。
- 在候选帧比较左右模型的预测位置和速度向量：
  - 最小速度夹角阈值为 `25` 度；
  - 左右位置衔接阈值使用自适应 RANSAC 阈值的 `2.0` 倍；
  - 左右两侧各至少需要 4 个内点，内点率至少为 `60%`。
- 增加轨迹状态：
  - `breakpoint_raw_kept`：真实突变候选，保留原始点；
  - `breakpoint_gap`：突变区间内的缺失点，不跨事件补点。
- 增加视频叠加：
  - 蓝点表示原始坐标；
  - 橙线表示事件轨迹；
  - 青线表示平滑轨迹；
  - 紫色菱形表示保留的突变点；
  - 红叉和红线表示异常点及其修正位置。

### 输出

- `cv/data/output/long4_ransac_trajectory_overlay.mp4`
- `cv/data/output/long4_xy_function_coordinates.png`

这一版按完整区间保护突变，后续发现会放过区间内的抖动点，因此在 2026-07-17 改为点级保护。

## 2026-07-14 - 连续异常段的两遍 Window RANSAC

### 背景

逐帧窗口拟合只排除当前帧。连续多帧异常点会在窗口中互相提供内点支持，污染拟合模型，严重时会把恢复后的正常点误删或纠正到错误轨迹。

### 改进

- 第一遍只计算原始点相对窗口 RANSAC 的残差，不修改轨迹。
- 使用前后各 20 帧的宽窗口检测可疑点。
- 将间隔不超过 2 帧的可疑点合并成连续可疑区间。
- 第二遍拟合时排除完整可疑区间及左右各 1 帧保护区。
- 普通点使用前后各 10 帧窗口，可疑点使用前后各 20 帧上下文。
- 只有满足以下条件才允许纠正：
  - 总内点率至少为 `60%`；
  - 目标帧左侧至少 3 个内点；
  - 目标帧右侧至少 3 个内点。
- 证据不足时使用 `ambiguous_raw_kept` 保留原始坐标。
- RANSAC 内点数量相同时，使用内点中位残差选择更稳定的模型。

### 输入与诊断输出

- 默认输入改为 `cv/data/output/long4_ball_coords_raw.json`。
- 增加完整轨迹的 `x(frame)` 和 `y(frame)` 坐标图。
- CSV 诊断字段增加初检残差、可疑点、左右内点数和模型可信状态。

### 验证

人工轨迹测试覆盖：

- 连续 4 帧异常；
- 连续 12 帧异常；
- 真实方向突变。

连续异常段能够整体恢复，异常段前后的正常点保持原始坐标。
